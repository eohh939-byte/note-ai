# 评估集设计（Eval Plan）

目标：在加功能之前，先给"整理文本"一个可验收的 baseline。所有指标都基于你的**真实样本**，不靠拍脑袋。

## 1. 数据集（20 条，先凑 3 类，各 ~7 条）
放入 `eval/samples/`，每条一个 `.md`，内容为「原始乱文本」：
- **课堂笔记**（你物理/高数课的随手记，含口语、跳步、重复）
- **网页剪藏**（复制来的文章段落，含广告/无关信息）
- **会议/待办**（零散要点、时间、人名）

另建 `eval/samples/<name>.expected.md` 写「人工期望的结构化要点清单」（用于人工/LLM 打分对照）。

## 2. 指标与门槛（上线门槛先拍，再调）
| 指标 | 定义 | 验收门槛 |
|---|---|---|
| 解析成功率 | Markdown→BlockNote 块不报错的比例 | 100% |
| 结构保真 | 原文关键信息点无遗漏（对照 expected） | ≥ 90% |
| 摘要准确 | 摘要未编造、概括到位 | ≥ 85% |
| 标签相关 | tags 与内容相关、可检索 | ≥ 85% |
| 无幻觉 | 未出现原文没有的事实/数据 | 0 容忍 |

## 3. 怎么测（MVP 手动版）
1. 对每条样本调用 `POST /api/organize`（或页面里粘贴整理）。
2. 检查：编辑器是否成功载入（解析成功）、关键信息是否在、摘要/标签是否对。
3. 记录 bad case，归类到「Prompt 问题 / 模型问题 / 样本问题」。
4. 改 `lib/prompt.ts` 后重测，确认无回归再合并。

## 4. 优化顺序（基于 bad case，不靠"改 Prompt"蒙）
- 漏要点 → 强化 Prompt 第 3 条（保留所有关键信息）。
- 有幻觉 → 强化第 3 条"绝对不要编造"，temperature 已压到 0.2。
- 结构乱 → 强化标题层级要求。
- 标签烂 → 给 few-shot 示例。

> 注意：先攒数据、先定门槛，再谈优化。没有评估集的"效果变好"都是错觉。
